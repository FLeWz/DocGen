# Decisions (open choices made)

## Milestone 1
- **Two DB roles.** `docgen` (superuser, from `POSTGRES_USER`) owns tables and runs migrations. `docgen_app` (LOGIN, NOSUPERUSER, NOBYPASSRLS, not owner, DML grants only) is what the API uses. Superusers and owners bypass RLS, so connecting as the owner would silently disable the second wall. The role is created/updated by `alembic/env.py` on every start (password = `APP_DB_PASSWORD`); default privileges grant DML on future tables. Tests assert the role is unprivileged.
- **RLS context** = transaction-local GUCs `app.org_id`, `app.user_id`, `app.invite_hash`, re-applied on every transaction begin. Empty -> NULL -> no rows. `ON DELETE CASCADE` runs as table owner (bypasses RLS), so deleting an org removes its children.
- **Non-org-scoped RLS exceptions** (deliberate, minimal): memberships are also readable by their own `user_id` (login, org list/switch); organizations readable if you have a membership; one invite row is visible when its token hash matches `app.invite_hash` (public lookup/accept). Writes always require `org_id = app.org_id`. `users` and `sessions` are not tenant tables and have no RLS.
- **Switching org** is the only endpoint taking an `org_id` from the client; it is checked against the caller's memberships (404 otherwise). Test enforces no other route accepts `org_id`.
- **Sessions**: opaque 256-bit token in an HttpOnly, SameSite=Lax cookie, SHA-256 hash stored in `sessions`, 14 days, no sliding renewal. `COOKIE_SECURE` env (false in dev; set true behind HTTPS).
- **CSRF**: double-submit. Cookie `docgen_csrf` (JS-readable) must equal `X-CSRF-Token` and carry a valid HMAC (SECRET_KEY) so it can't be forged from a sibling subdomain. Not bound to the session. Applies to all unsafe methods including login/signup/accept.
- **Roles in an org**: admin may manage members up to admin and invite up to admin; only owners grant/modify owners; last owner can't be demoted/removed; anyone may leave (self-delete) unless last owner. Everyone in the org can list members; invites are admin+. Insufficient role -> 403 (the caller already belongs to the org); foreign org objects -> 404.
- **Removed members / deleted orgs**: the session's active org is validated against membership on every request; if gone, the user has no active org (400 on org endpoints, can create/switch).
- **Invites**: raw token only in the email; SHA-256 stored. Resend rotates the token (old link dies) and resets expiry; resending an expired invite revives it. One pending invite per email per org (409). Accepting requires the logged-in email to equal the invite email; unknown-email accept creates the account (email proven by token) and logs in; existing email requires login first (401). Public lookup is `POST /api/invites/lookup` (token in body, not URL/logs) and reveals `user_exists` to the token holder. Single use is enforced with an atomic `UPDATE ... WHERE accepted_at IS NULL`. Expired/used/revoked -> 410, unknown -> 404. If SMTP fails the invite is still created and `email_sent=false` is returned.
- **Emails** normalized to lowercase; signup of an existing email returns 409 (user enumeration accepted for now; no rate limiting yet).
- **Password**: min 10, max 128, argon2id defaults. Login does a dummy verify for unknown users.
- **Ids**: UUIDv4 generated in Python. Roles stored as varchar + CHECK (no PG enum).
- **Sync SQLAlchemy** (psycopg 3, sync endpoints on FastAPI's threadpool); simplest with per-request RLS context.
- **Frontend** (superseded by the UI round: react-router, see below): no router library (path switch on `/accept-invite`), plain forms, TanStack Query; dependencies pinned via `package-lock.json`, `npm ci` in Docker.
- **nginx** `web` is the only published app port (`WEB_PORT`); Mailpit UI on `MAIL_UI_PORT`; db/api/pdf are not published. Compose project name fixed to `docgen`.
- **Tests** run in the api image (dev deps included, one image) against a separate database `docgen_test` created on demand; tables truncated per test. Mail is stubbed in tests, real Mailpit used in the compose smoke check.
- **`.env` required**: compose refuses to start without secrets; `make up` copies `.env.example` if `.env` is missing.

## Milestone 2
- **Git via CLI** (`app/git/repo.py`): fixed argv, no shell, `git` in the api image. Commits are built with plumbing (temp index, `hash-object`, `write-tree`, `commit-tree`, `update-ref HEAD new old`) so bare repos need no worktree and a moved HEAD makes the commit fail. Revs from clients must be a 7-40 hex sha or a tag name (`refs/tags/<name>`), never `HEAD`/ranges/options. Repo paths come from UUID objects only and are checked under `REPOS_ROOT`; deleting a folder/org rmtree's its repos after the DB commit.
- **Snippet files**: `snippets/<slug>/content.json` (sorted keys, indent 2, so equal content is byte-equal and diffs are stable) + `meta.yaml` (id first). Rename = dir move in the next commit; old versions are found by the uuid in `meta.yaml` (`git grep`), so history/diff work across renames.
- **Per-snippet history** uses `Snippet-Id: <uuid>` trailers the server appends to each commit message (user-supplied lines of that form are stripped). Commits made outside the app have no trailers and won't show in snippet history.
- **Draft base** = snippet's `head_sha` when the draft was created (NULL for new snippets). Conflict = `draft.base_sha != snippet.head_sha` (another commit touched *this* snippet), not any HEAD movement. An untouched draft (equal to its base) silently follows HEAD. Resolve = PUT merged content and re-base onto HEAD; commit then succeeds. 409 body: `detail = {error:"conflict", conflicts:[{base, theirs, mine, ...}]}`.
- **Commit order**: lock folder row (`FOR UPDATE`) -> DB slug/title flush -> git commit -> DB commit; a git failure rolls the DB back. A crash between git and DB commit leaves a stale index row (HEAD sha behind); no repair job yet.
- **Roles**: viewer reads (incl. changes/history/diff); editor creates/renames/moves folders, snippets, drafts, commits, tags; admin deletes folders (destroys history). New snippets are DB rows without a commit until first committed (visible to the org with `head_sha: null`).
- Display name already existed on `users.name`; no migration needed. No snippet delete endpoint yet.

## Milestone 3
- **Org style set** (`styles`, tenant table, seeded per org at signup/org create and backfilled by migration 0003): Normal, Title, Heading 1-4 (decimal numbering), Quote, Code, List Paragraph, Table Grid. Content never references a style by uuid but by `style_id`, a Word-style id (`Normal`, `Heading1`), unique per org. Reason: a base document's `styles.xml` uses the same kind of ids, so snippets keep working when a base doc supplies the styles. `style_id`/`kind` are immutable after creation; built-ins can be edited but not deleted; admin writes, everyone reads. Deleting a custom style that content still names is allowed: renderers fall back to `Normal`/`HeadingN`.
- **Base-doc override hook (for M4)**: all style reads go through `app.styles.resolve(repo, base_doc=None)`. M4 implements "styles for base doc X": base doc styles (parsed from its styles.xml, matched by `style_id`) override org styles of the same id; org styles fill ids the base doc lacks (the base doc may instead mark itself "replace", then only its set is offered). The editor/preview take a `Style[]` and don't care where it came from; the API will grow an optional `?base_doc=` on `GET /api/styles`.
- **Content JSON shapes** (TipTap v3; `null` attr = default): `paragraph {styleId|null}` (null = `Normal`, or `ListParagraph` inside a list); `heading {level 1-4, styleId|null}` (null = `Heading<level>`); `table {dynamicList|null}` + `tableRow`/`tableHeader`/`tableCell {colspan, rowspan, colwidth}` (merged cells = colspan/rowspan); `variable` inline atom `{name, default, filter|null}` with filter `upper` or `date:<format>` (e.g. `date:YYYY-MM-DD`); `image` block atom `{imageId, alt, width|null}`; marks `bold`, `italic`, `underline`, `link {href}`; lists `bulletList`/`orderedList`/`listItem`. Variable names: `^[A-Za-z_]\w*(\.\w+)?$`; `row.*` is bound by the enclosing dynamic table and not declared; `doc.*`, `org.*`, `author`, `revision_history`, `linked_documents` are builder built-ins and not declared either. **Dynamic table convention: the last row is the row template**; its cells use `row.field` variable chips.
- **Draft `styles`/`variables`** are computed client-side on every autosave (`extractStyles`, `extractVariables`) and are lists of names only (style ids; variable names incl. dynamic-table list names). Defaults/filters live in the node attrs; the server does not re-derive them.
- **Images**: `POST /api/images` (editor+, multipart `file`, max 10 MiB) is validated by opening the bytes with Pillow (png/jpeg/gif/webp only, no SVG; type from the bytes, never the filename/Content-Type; pixel cap against decompression bombs). Stored at `/files/{org_id}/images/{image_id}.{ext}` (path built from UUIDs, never from the client); `GET /api/images/{id}` is session-authenticated, org-scoped, `nosniff`. Content references images by `imageId` only (never a URL), so renames and old versions don't break. At commit, every referenced image is copied into the git tree as `snippets/<slug>/assets/<imageId>.<ext>` (rename moves the dir along), making the repo self-contained for export. Limits: assets no longer referenced are not pruned from later trees; uploaded images are never garbage-collected from `/files`.
- **Preview** = pure `contentToHtml(doc, styles)` (`frontend/src/editor/render.ts`): A4 page, 2.5 cm margins, style values inlined per block, decimal heading numbering by style level, escaped output, links limited to http/https/mailto. Variable chips show their default (filter applied for `upper`) else `{{ name }}`.
- **Autosave**: 800 ms debounce, PUTs chained so a slow earlier save can't overwrite a later one, flushed on unmount and before "Commit…". The editor reloads server content only on an explicit reload (restore/discard/resolve) or when HEAD/base moved and nothing is unsaved.
- Not done in M3: UI for the org style set (API only), character styles/table styles in the editor (stored, not applied), image resize UI.

## Milestone 4
- **Base documents** live in `/repos/{org}/_base.git` at `base/<id>.docx`; every upload is one commit and one `base_doc_versions` row (number, sha, filename, parsed `styles`, `placeholders`). The sha is the version id that documents pin. No delete endpoint yet. Upload validation (`app/base_docs.py`): <=25 MB, real zip with `[Content_Types].xml` + `word/document.xml` + the Word main content type, no macros/encryption/`..` paths, <=2000 entries, decompressed bytes counted while reading (<=200 MB and <=100x ratio), every `.xml`/`.rels` parsed with defusedxml `forbid_dtd=True` (XXE and entity bombs rejected as 422), then opened with python-docx. python-docx/lxml only touch files that passed this at upload.
- **Placeholders** are whole paragraphs: `{{ CONTENT }}` and `{{ SLOT:name }}`. A base doc without CONTENT is accepted and reported (`placeholders.content=false`); exporting with it fails with a clear error.
- **Styles from a base doc**: `styles.xml` -> Style-shaped rows (no `basedOn` resolution, values sanitized to satisfy `StyleOut`). `resolve(repo, base_doc)` lets base styles override org styles of the same id and keeps org styles for the rest ("replace" mode not implemented). `GET /api/styles?base_doc=<id>` uses the head version.
- **Bundled default** (`default_docx()`): python-docx template + Normal/Title/Heading1-4, header/footer with PAGE/NUMPAGES fields, revision-history and linked-documents tables as docxtpl `{%tr %}` rows, `{{ CONTENT }}`. Created on demand (`POST /api/base-documents` without a file, admin) and used for exports when a document pins no base document. Milestone 4 export *removes* the `{%tr for ... endfor %}` rows (tables keep their header); milestone 5 fills them.
- **Documents** are rows in `documents` + `documents/<slug>.yaml` (id, title, base_document{id,version=sha}, blocks, variables{declarations,values}, links). Drafts are per user (`document_drafts`), created by the first edit/PUT. They are committed through the existing folder commit (`document_ids` next to `snippet_ids`, trailer `Document-Id:`), and `changes` lists them with `kind:"document"`. No 3-way merge: if the head moved since the draft started, commit returns 409 and the draft has to be discarded. Slug rename = delete old file + write new in one commit. Delete = final commit removing the file + DB row.
- **Blocks**: `snippet_ref`, `heading{text,level,styleId,numbered}`, `page_break`, `toc`. "Slot content" is the `slot` field on every block (default `CONTENT`, or a named slot of the base doc); there is no separate slot block type. Block ids are server-assigned uuids when missing (used by bump endpoints).
- **Pins**: `commit` (sha, abbreviations normalised to full), `tag`, `latest`. The referenced folder and snippet must be in the caller's org and the snippet must have a commit, else 404/422 (same body for "other org" and "does not exist"). Default pin from the UI = the snippet's head commit. At export, tags and `latest` are frozen to commit shas.
- **Update available** = pin resolves to a commit whose snippet content differs from head (`C.same`), `newer_commits` = commits with the snippet's trailer in `pin..head`. `latest` pins never show it. Bump preview uses `C.diff`; bump apply writes `{commit, head sha}` into the user's draft.
- **Used by** is an index (`document_refs`) written when a document is committed (one row per snippet block per commit); drafts are not included. Deleting a document deletes its rows.
- **Library** (`GET /api/library/snippets?q=&tag=&folder_id=`): committed snippets only, grouped by folder. `tag` keeps snippets that exist at a commit carrying that tag in their own folder.
- **Export** = `exports` row doubling as the job (queued/running/done/error). `GET /api/documents/{id}/export?format=docx` (GET per the API spec) builds a self-contained `spec` (working copy = draft else head, resolved pin shas, base pin, variables, built-ins incl. the date) in the request, then a 2-thread pool in the api process renders it. `GET /api/exports/{id}` polls, `/download` serves the file. Because the queue is in-process, a restart can strand a row: rows still queued/running after 10 minutes are reported as error. Re-rendering the stored spec gives the same bytes (`export.render_docx`). Exports of a draft are reproducible because the spec snapshot is stored. PDF plugs in as `export.RENDERERS["pdf"]`.
- **Determinism**: fixed core properties (date from the spec), zip entries re-packed with fixed timestamps, numbering/rId/docPr ids are sequential, no random ids.
- **OOXML mapping**: paragraph/heading `styleId` written as `w:pStyle` if the base doc has that style id (else HeadingN, else none = Normal); no direct fonts; bold/italic/underline/link marks as run properties (links only http/https/mailto); lists reuse a base-doc abstractNum with bullet/decimal at level 0 (not tied to a paragraph style) or add one, every ordered list gets its own `w:num` with level restarts; numbered heading blocks use a multilevel numbering, unnumbered ones get `numId 0`; tables via python-docx with `gridSpan`/`vMerge` for col/rowspan (nested tables are skipped with a warning); images from `snippets/<slug>/assets/` at the pinned commit (webp converted to PNG), alt text kept. TOC = dirty complex field + `w:updateFields` in settings.
- **Variables in export**: chips become `{{ name|default(..)|upper|datefmt(..) }}` text runs and, like all `{{ }}` text in the base doc (body, headers, footers), are rendered by a sandboxed jinja env (`*`, `**`, `<<` blocked, no `{% %}`); values are written as XML text nodes so markup in values is inert. Placeholders split across runs are merged into the first run (its formatting wins). Undefined names stay as `{{ name }}` and are listed in the export warnings. Dotted names (`a.b`) become nested dicts. `doc.version` = short head sha or `draft`.
- **Frontend**: native HTML5 drag & drop (library -> blocks, handle -> reorder) plus "Add" buttons; document draft autosave (800 ms) like the snippet editor; preview reuses `contentToHtml` with `?base_doc=` styles; the commit tab handles documents. Not built: restore of an old document version, per-block "view source snippet" link, editing which tags a library filter offers.

## Milestone 5
- **No docxtpl.** The sandboxed jinja env from M4 is kept: docxtpl would need the whole DOCX as one template (and runs unsandboxed unless wrapped); the per-text-node render plus `expand_rows` is ~40 lines and keeps the "values are XML text nodes" guarantee. The base doc still uses docxtpl *syntax* (`{%tr for x in list %}` ... `{%tr endfor %}`), so Word users can author it the usual way. Autoescape stays off on purpose: output goes through lxml text nodes, which escape; turning it on would double-escape.
- **Row repetition** (`docx_export.expand_rows`) is the single mechanism for base-doc tables and for snippet tables marked `dynamicList`: the snippet builder wraps the template (last) row in `{%tr for row in <list> %}` / `{%tr endfor %}` marker rows, so both paths are one code path. Rows between the markers are deep-copied per item and rendered with the item bound (`row`, or the loop variable of the base doc). Only `for x in name[.sub]` is understood; anything else drops the rows with a warning. A list row is a dict whose missing columns render empty (not as a missing variable); `None` renders empty everywhere in revision/linked rows.
- **Render once.** Nodes rendered inside repeated rows are remembered, so a value like `{{ 7*7 }}` typed by a user is never evaluated by the later whole-document pass. Tests cover `''.__class__` style payloads in base doc, snippet text and values (sandbox returns Undefined/raises; text stays inert).
- **Variable types**: `text|date|number|list` (`list` = list of objects; declaration has `columns`). Validated on draft save (422): date = ISO string, number = int/float, list rows = flat objects (<=1000 rows, <=20 fields, scalar values). The built-ins and `row.*` are still never declared.
- **Required variables** (checked at `GET .../export`, before a job exists; 422 `detail = {error:"missing_variables", message, variables:[{name,type}]}`): every *declared* variable, and every chip in pinned snippets without its own default, and every `dynamicList` name, that has neither a value (non-null, non-empty string; `[]` counts as a value) nor a declared default. Variables only referenced by `{{ }}` text of the base document are not pre-checked (would need the base parsed before the job); they stay warnings in the export record.
- **Revision history**: `documents/<slug>.yaml` gets `revision_history: null | [{version,date,author,message}]`. `null` = auto: commits of the document file (`Document-Id` trailer) plus, per pinned snippet, its commits reachable from the pin sha (`Snippet-Id` trailer, so commits newer than the pin don't leak in), de-duplicated by sha, oldest first; version = a tag on that commit else the 7-char sha; message = first line without trailers. Non-null = hand-edited rows used as is ("Reset to auto" sets null again). `GET /api/documents/{id}/revision-history` returns the auto rows for the builder preview. The result is frozen into the export spec. Commits made outside the app (no trailers) are not listed.
- **Linked documents** rows come from `links` (`title`, `doc_id`/`id`, `version`, `url`/`link`).
- Existing documents/drafts without the new key behave as `revision_history: null`; no migration.
- Builder UI: typed variable form (date/number inputs, list editor with columns), revision table with inline editing, missing-variable list with a "Declare" shortcut for undeclared names.

## Milestone 6
- **PDF** = the same DOCX bytes posted to Gotenberg `POST /forms/libreoffice/convert` (`PDF_URL`, httpx, `PDF_TIMEOUT_S`=120, `PDF_MAX_BYTES`=100 MiB counted while streaming, body must start with `%PDF`). Every failure becomes the export row's `error` ("PDF service unavailable", "timed out after Ns", "HTTP 500: <first 200 bytes>", "larger than ...") and download answers 409 like any failed export. No retries.
- **Field refresh**: Gotenberg's `updateIndexes=true` makes LibreOffice rebuild the TOC and evaluate PAGE/NUMPAGES during conversion; verified live (heading shows up in the TOC and body; footer "Page 1 of 1"). The DOCX itself still only has dirty fields + `updateFields`, so Word asks to update on open.
- **Determinism**: DOCX stays byte-identical per spec; PDFs are not promised to be (LibreOffice embeds creation time/ids). The stored spec re-renders the same content.
- Tests: mocked Gotenberg (HTTP server in a thread) for success/500/non-PDF/oversize/timeout/unreachable, plus a live test against the compose `pdf` container (skipped when unreachable) using pypdf for page count and text.

## Milestone 7
- **Import = tenant table `imports`** (`content` JSONB = editable TipTap doc, `warnings`, title, filename) + the original package at `/files/{org}/imports/{id}.docx` (UUID path). The editor saves straight to the row (PUT, 800 ms debounce like drafts; one editable copy per import, not per user). No delete endpoint yet. Upload goes through `base_docs.validate` (zip structure, 25 MB, bomb guard, defusedxml, macros) and then lxml with entities/DTD/network off; `word/document.xml` capped at 30 MB.
- **Parser** (`docx_import.py`): paragraphs/headings (heading = style whose `styles.xml` outline level or id says 1-4; `styleId` = the Word style id, kept), runs with bold/italic/underline, external http(s)/mailto hyperlinks, tables (`gridSpan` -> colspan, `vMerge` -> rowspan, first `tblHeader` row -> `tableHeader`, column widths from `tblGrid`), pictures (png/jpg/gif/webp -> image store via the existing validation, `alt` and width kept), lists (direct `numPr` -> bullet/ordered by the numbering.xml format, nesting by ilvl, `numId` kept as a list attr). Extra attrs `numId` (lists) and `styleId`/`tblPr`/`grid` (tables) are invisible TipTap global attributes.
- **Opaque blocks** = `opaque {kind, xml}`, block granularity: a paragraph with anything unsupported inline (text box, field, content control, equation, SmartArt/chart, comment, tracked change, footnote ref, page break, internal link, section break, legacy objects) becomes one opaque block holding the raw OOXML (with all in-scope namespace declarations), as do body-level unknown elements (sdt, customXml...), nested tables and tables with tracked/irregular rows. One warning per kind with a count. A fragment that would be refused on write-back (see below) is replaced by a visible stub paragraph and listed as "blocked".
- **Write-back validation** (`ooxml.opaque_element`, applied on PUT, on export and when a snippet containing opaque blocks is exported): defusedxml (`forbid_dtd`) then lxml `resolve_entities=False`; root must be a Word element (not `sectPr`); denylist `altChunk`, `subDoc`, `externalData`, controls (OLE objects: round 9 policy); field instructions DDE/INCLUDETEXT/LINK/MACROBUTTON/... refused; every `r:*` attribute must name a relationship that exists in the target package. PUT answers 422 on a bad fragment, so export of stored content cannot hit one. Table `tblPr` goes through the same check.
- **Export** = original package with the body replaced (`docx_import.export`): python-docx opens the original, drops every body child but the final `sectPr`, and the exporter's `Builder` (same code as snippet export) writes the content back. styles/numbering/theme/settings/headers/footers/media parts come through (round-trip test compares canonical XML). Import mode (`Builder(rels=...)`) differs from snippet mode in three ways: opaque XML is written verbatim and keeps its `r:id`s; lists reuse their original `numId` when it still exists in numbering.xml (numbering continues across lists); tables restore `tblPr` and `tblGrid`/`tcW`. In snippet mode (selection snippets exported through a document) opaque blocks with relationships are skipped with an export warning, Word 2010+ attributes (`w14:paraId`...) are stripped, and tables use `styleId`/`TableGrid`.
- **Selection** = a range `[start, end)` of top-level block indexes of the stored content (the UI maps the TipTap selection to it after flushing the autosave). The snippet is created as a draft (no commit) with the blocks as they are: style ids and `imageId`s unchanged; images are not copied at this point because they already live in the org image store and the normal commit copies them into the repo. **Split** cuts before every Heading <= level (1 or 2); text before the first heading becomes "Front matter" (skipped if only empty paragraphs); preview is a GET, apply a POST that creates one draft per section in one transaction (max 200).
- **Use as base document** (admin): the original package with the body replaced by a `{{ CONTENT }}` paragraph, stored through `_store` of the base-document router (new base doc, or a new version of an existing one with `base_document_id`).
- **Not kept (listed in warnings with counts):** direct run formatting (font, size, colour, character styles), direct paragraph formatting (alignment, spacing, indent), bookmarks, links to non-web targets, cell shading/borders (table-level properties are kept). Heading detection does not resolve `basedOn`. List items inside a list nest by ilvl order, so a list starting at ilvl 2 is exported at depth 0. Not verified in Word itself, only python-docx, LibreOffice (Gotenberg converts the exports) and structural tests.

## Milestone 8
- **Login throttling** (`app/throttle.py`): failed attempts in process memory, 5 per (ip, email) and 20 per email in 10 min -> 429 + `Retry-After`; a success clears the ip+email counter. The right password is refused too while throttled (else the throttle could be bypassed by guessing). State is per worker and lost on restart (one worker runs); move to a DB table/Redis when scaling out. uvicorn runs with `--forwarded-allow-ips '*'` so the ip is the one nginx puts in `X-Forwarded-For` (the api port is not published, only nginx reaches it). Signup email enumeration (409) is accepted and documented; signup is not throttled. CSRF stays signed double-submit, not session-bound (SameSite=Lax cookie + HMAC); a second cookie is not worth it.
- **Seed** (`app/seed.py`, `python -m app.seed`, run by `entrypoint.sh` when `SEED_DEMO=1`): drives the real API through an in-process `TestClient` (RLS, git and validation are exercised; no second code path), with `mail.send_mail` swapped for a capture to read invite tokens. Idempotent: skipped when `owner@example.com` can log in and "Demo Org" has the sample import (the last step = completeness marker); a partial earlier run is wiped (org deleted, users reused) and redone. Errors never block the api from starting. The sample DOCX comes from `tests/fixtures/sample.py`, which ships in the image (needs only python-docx/Pillow, both runtime deps). The demo password is public (`demo-password-123`): dev only; `.env.example` sets `SEED_DEMO=1`, compose defaults to 0 when unset.
- **Deletes**: `DELETE /api/snippets/{id}` (editor): 409 while a committed document version (`document_refs`) or any draft mentions it; a committed snippet is removed from HEAD in a final commit (history/tags stay), an uncommitted one disappears with its drafts. `DELETE /api/imports/{id}` (editor): row + original file. Org deletion now also removes `/files/{org}` (it only removed repos before).
- **Cleanup** `POST /api/maintenance/cleanup[?dry_run=true]` (admin, own org only): deletes images older than 24 h that no draft, import or git commit of the org names (`git log --all --name-only` finds `assets/<imageId>.<ext>`; an image that ever entered a commit is kept, history/restore still shows it) and files under `/files/{org}/{images,imports,exports}` older than 1 h without a DB row. Manual, no scheduler.
- **Style-set UI**: collapsed "Style set" section on the dashboard (`Styles.tsx`), a table with one form per row; admins edit (PATCH) and add/delete custom styles, others read. `style_id`/`kind` stay immutable.
- **Docker e2e** (`make test` = backend + Vitest + e2e): compose service `e2e` (profile `e2e`, `mcr.microsoft.com/playwright/python` pinned to the playwright version, repo-root build context narrowed by `.dockerignore`) runs `smoke, docbuilder, import, invite` against `http://web` and Mailpit `http://mail:8025`. The DOCX fixture is baked into the image (`E2E_SAMPLE_DOCX`) because the container has no docker. `web` got a healthcheck so `up --wait`/`depends_on` work. The scripts sign up throwaway users in the running stack and retry the first keystrokes in the editor (typing right after a new snippet opens can be swallowed when its draft loads).
- **Acceptance**: `scripts/clean-start.sh` = fresh `git clone` into a temp dir, `.env` from `.env.example` with other ports, `docker compose -p docgen-clean up --build --wait`, login as the seeded owner, volume backup, `down -v`, restore, start with seeding off, check the data, tear down (volumes included). It always passes `-p docgen-clean`.

## Round 2

### Fidelity limits (what is still not like Word)
- Preview is HTML/CSS: line breaking, hyphenation, kerning, justification and font metrics differ (Calibri/Cambria/Arial map to Carlito/Caladea/Liberation Sans; other fonts fall back to generic serif/sans). Page guides are an estimate (fixed body height, no widow/orphan control, no keep-with-next), not real pagination. Only the "Render as Word does" PDF (LibreOffice, not Word itself) paginates.
- Header/footer: only the default header/footer of the final section; first-page/even-page variants, other sections' page setup, columns and section-specific margins are not shown. PAGE/NUMPAGES show their cached value.
- Floating objects (anchored images, text boxes, shapes) are drawn inline at their paragraph, not positioned; WordArt, charts, SmartArt, equations are chips (embedded OLE documents: round 9). Images inside opaque blocks need a raster format and the media caps above.
- Not kept as editable formatting (counted in the import warnings): character spacing/kerning, text effects, paragraph tab stops (default 36 pt tabs are drawn; right tabs with leaders only inside opaque TOC lines), frames, widow control, outline levels other than via style, bookmarks, comments. Highlight becomes shading. Theme colour links are flattened to the resolved colour (changing the theme later will not recolour them).
- Tables: borders/shading/widths/vAlign/merges are kept; conditional table-style formatting (banded rows, first-column) and cell margins are only drawn where written as direct formatting; nested tables stay opaque; table style paragraph defaults apply to the default paragraph style only.
- Lists: format and nesting follow numbering.xml per level, but bullet glyphs are limited to disc/circle/square, restarts/continuation across separated lists are not drawn (each list restarts at 1 in the editor; the exported file keeps the original `numId`), and level indents come from the browser, not numbering.xml.
- Editor adds no UI for colour/font/size (they are preserved and rendered, only alignment is a toolbar button); styles are chosen from the style dropdown.

## Round 6: base documents management, unique names, split by headings

- **Unique names.** Migration 0007 trims names, renames later duplicates (case-insensitive, by `created_at`) to `X (2)`, `X (3)` (never deletes), then `CREATE UNIQUE INDEX uq_base_documents_org_name ON base_documents (org_id, lower(name))`. The API checks first (`new_base`, case-insensitive on the trimmed name) and answers `409 {error: "name_exists", base_document_id, name, current_version}` (also under `detail`, so the SPA's error type carries it); the index is the backstop for races (plain 409). Applies to create, rename (`PATCH /base-documents/{id}`) and use-as-base from an import. "Create a new version instead" is client-driven: it calls the existing `POST /base-documents/{id}/versions` or `POST /imports/{id}/base-document {base_document_id}` with the id from the 409 (no `on_conflict` parameter).
- **Delete.** `DELETE /base-documents/{id}` (admin): under the org's `_base.git` advisory lock it looks for documents whose HEAD version or any user's draft pins the base document; if any, `409 {error: "in_use", documents: [{document_id, folder_id, title, state}]}` and nothing changes. Otherwise the DB rows go (versions cascade) and one commit in `_base.git` deletes `base/<id>.docx`; history stays, so exports already rendered from a pinned sha still re-render. Exports do not block deletion (only counted in `GET /base-documents/{id}/usage`). Older committed versions of a document that pinned it are not checked: they only matter when restored. No `force` option.
- **Usage cost.** `_usage` reads every document's HEAD yaml from git once per list call (N git reads); fine for hundreds of documents, add a `document_base` index table if it grows.
- **Split.** `GET /imports/{id}/headings` lists top-level heading blocks (`index`, `level`, `title`, `blocks` and `chars` up to the next heading). `POST /imports/{id}/split` takes `headings` (block indexes) + optional `titles {index: title, -1: preface title}` + `preface`, or the old `level`; exactly one of `level`/`headings`. ## Round 8: table editing

- **One source of truth for widths: `attrs.grid`** (twips, one entry per grid column). The cells' `colwidth` (px, 15 twips) are derived from it by `applyGrid` after every operation that touches widths; the exporter writes `tblGrid` from `grid`, falls back to the cells' colwidth when the grid does not fit the columns (`grid_from_cells`), and writes `tcW` for *every* `tc` (vMerge continuation cells too) as the sum of the grid columns it covers. `gridGuard` (ProseMirror `appendTransaction`, only tables touched by the transaction) repairs a grid whose length no longer matches (paste), never an intact one, so unedited tables keep `attrs.orig` and their original XML.
- **`tfmt` is what is drawn, `tedit` is what the exporter writes.** `tfmt` also holds the values resolved from the table style; writing it back would turn style values into direct formatting (the round-trip test caught it). `tedit` (hidden attr) holds only what the user set (jc, width, layout, ind, mar, bdr); `fmt.write_tbl` writes it into the kept `tblPr` in schema order, a dxa `tblW` follows the grid sum unless the user set a width. The old ribbon's `tfmt.jc` still works. A drag/resize makes the table `fixed` with a dxa width = grid sum; *to contents* = `autofit` + `auto` width, *to window* = `autofit` + 100 %, with the grid measured/scaled so the export has a consistent `tblGrid`.
- **Operations** (`frontend/src/editor/tables.ts`): prosemirror-tables does the merge arithmetic (delete column through a merged cell shrinks the colspan, delete row that starts a vertical merge moves the start down); wrappers add what it lacks: the inserted cells/rows clone the neighbour's `cfmt`, `eff`, paragraph style and the row's `rfmt`, a new column takes half of its neighbour's width (table width unchanged), split cells inherit the merged cell's formatting, the whole grid is rewritten in the same transaction. Every operation is exactly one transaction with `closeHistory` (two quick operations stay two undo steps, a drag is one), selection stays in the table. Refusals (null, a toast in the UI): last row/column (delete table instead), moving a row across the header boundary / through a vertical merge / the dynamic template row, duplicating or moving a column with merged cells, sorting with vertical merges.
- **Borders** are written on both cells of a shared edge, so the browser's collapsed border and Word/LibreOffice resolve the same line; the borders of a selection (all/outside/inside/side) are computed on grid edges, edges inside a merged cell are skipped.
- **Overlay geometry** uses `getBoundingClientRect` (visual px, CSS `zoom` already applied) and converts drag distances with the table's own factor `rect.width / offsetWidth`, so it is zoom independent (tested at 75/100/150 %). Row handles use the real `tr`s of the model (via `view.nodeDOM`), so page-gap rows and repeated header clones of the pagination are skipped; tables of page headers/footers (`.ox`, inside `.pgsep`) are drawn decorations and get no handles. Column grips sit above row grips at crossings.
- **Dynamic table from existing rows.** The conversion lives in `dynamic.ts`; the defaults travel on the table node (`dynamicRows`, `dynamicCols`) so snippets, imports and the document builder share one mechanism: the server derives the declaration `{name, type: list, columns, default: rows}` (`docx_vars.table_decls`; validation: <= 1000 rows, <= 20 columns, scalar values) and (a) stores it in the import's variables on every save, (b) hands it to *Use as base document* (so it shows under Base document > variables as an editable list), (c) lets the exporter use the table's own rows when neither the document nor the base gives the list (`ctx.setdefault`), and (d) does not count the list as a missing required variable. Values given in the document override the defaults. Values with line breaks are rendered as `<w:br/>`. Round trip tested: import -> make dynamic -> use as base -> build without override = original cell text, with the template formatting; with an override the template row repeats.
- **Measured on the real NANOhpc-obc Linux Manual import (12 tables)**: the drawn column widths are within 0.8 % of their `tblGrid`; after a drag the LibreOffice PDF puts the column texts exactly where the model's grid says (140.3 / 213.2 / 319.8 pt vs 140.3 / 213.2 / 319.8 on the synthetic fixture).
- **Not done / known gaps.** *Toggle first column* (needs `tblLook` edits and re-resolving the style's conditional formats, `eff`): not implemented. *Table style* change drops the derived `eff` of the cells and relies on the `ts-<id>` CSS of the look, conditional formatting of the new style is approximate in the editor; Word applies it fully. Table-level cell margins have no UI (per cell padding does; the exporter supports `tedit.mar`). The table-resize corner scales widths only, not heights. Nested tables are still opaque. Text-to-table/table-to-text are text only (chips and run formatting are not carried). Word was not available: all rendering comparisons are against LibreOffice (Gotenberg).

## Round 9: base documents editable, revision table, embedded documents, layout, scrollbars

### D. `[embedded object removed: OLEObject not allowed]` (root cause and policy)
- **Root cause.** `OLEObject` was on the `FORBIDDEN` list of `ooxml.opaque_element`. The importer (`_Parser.keep`) validates every opaque block with it, and a block that fails was *replaced by a paragraph of visible text* `[<kind> removed: <reason>]`. The user's manual has one `w:object` (`ProgID Word.OpenDocumentText.12`, `Type=Embed`, `DrawAspect=Content`, `word/embeddings/oleObject1.bin` = an OLE compound file wrapping an OpenDocument text with the code block, preview `media/image3.emf` as VML `imagedata`), so imports/bases made from it carried that text into the PDF.
- **Policy.** An embedded document is a first-class case: never executed, never parsed by us (only magic bytes, size and name checks), written back byte for byte. `opaque_element` accepts `o:OLEObject` when `Type=Embed` and its `r:id` is a relationship of the target package (a snippet's block carries its parts, below). Dropped at upload (`ooxml.neutralize_ole`, run for every import and every base-document upload/version): `Type=Link`, external/UNC/file/http targets, targets outside `word/embeddings/`, `Package`/`OLE2Link`/`Forms.*`/shell ProgIDs, blobs > 10 MB, blobs containing `vbaProject` or UTF-16 `VBA` (macros), and binaries that are not a known document container (CFB/zip/pdf/png/jpeg/gif/rtf magic) but look like executables (`MZ`, ELF, `#!`, NUL bytes). Dropping removes the `OLEObject` element, its relationship and its part; the preview picture stays as a plain VML picture, the reason is in the import warnings (base documents: in the git commit message). DDE/`INCLUDETEXT` fields still refuse the block, but the block is now an *empty paragraph* plus a `blocked` warning: no code path injects visible placeholder text any more. Uploads pass `base_docs.validate` first (zip bombs, XXE, `vbaProject.bin` entries).
- A normal embedded document gets no warning: the opaque-block line reads `1× embedded object: embedded document kept as is`. Admin-uploaded bases are not trusted more than editor uploads in code (the checks are cheap); the difference is only who can create them.
- **Editor.** `ooxml.ts` draws `w:object` as its preview picture at the VML size when the server sent it as raster (PNG/JPEG/GIF/WebP); an EMF/WMF preview (the user's manual) cannot be drawn by a browser, so it is a sized box labelled `Embedded document (<ProgID>)`, never a grey chip. Not done: converting EMF to PNG, showing the embedded text in a tooltip (needs a CFB reader).
- **Snippets.** Selection/split snippets take `attrs.parts = [{rid, kind: image|oleObject, ext, b64}]` (<= 3 MB, only `word/media|embeddings`, rechecked with the same size/magic rules). `Builder.with_parts` re-validates every part at export, adds it with `next_partname` and a new relationship id of the target package and rewrites the `r:*` ids; content types come from python-docx. Two uses of one snippet = two embedded parts. Round 7's "opaque blocks with relationships are skipped in snippet export" is lifted for pictures and embedded objects (other relationship kinds, e.g. hyperlinks, still skip).
- **Checked on the real manual** (local copy, imported, `render/pdf` against LibreOffice of the original file): 11 pages both, 0.00 % pixel difference on every page at 50 dpi including the object's page; no `embedded object removed` in `pdftotext`. Imports/bases created before the fix still hold the old text block: re-import the file, or *Edit* the base, delete the paragraph and re-insert the object by re-importing.
- Limits: macros inside an embedded OOXML package whose entries are deflated are not detected (only stored names/UTF-16 stream names are); embedded CFB/ODF contents are not opened.

### A. Editing base documents
- **Session = an `imports` row** linked to the base document (`base_document_id`, `base_sha` = version it started from, `base_fp` = block fingerprints; migration 0008), one per (user, base document), hidden from the import list and from other users (`_get` answers 404, also for the owner). `POST /base-documents/{id}/edit` (admin) parses the head version like an upload (`D.parse`): unedited blocks keep their original XML and every package part survives (`D.export` writes into the original package). Same editor, so page view, header/footer editing, Structure, table tools, `{{ CONTENT }}`, variable chips and dynamic tables come for free. Autosave is the import `PUT`.
- **Commit** `POST /imports/{id}/base-commit {message, override}` (admin): `D.export(orig, content, asset)` without `render` (so `{{ }}`/`{%tr %}` stay in the file) -> `base_documents._store` = the upload path (validation, `_base.git` commit with the user as author, `BaseDocVersion`, placeholders/variables parsed, defaults of dynamic tables merged). Response: version, sha, placeholders, variables, warnings (e.g. no `{{ CONTENT }}`). The session is consumed. **Conflict**: head version is not `base_sha` -> `409 {error: base_changed, head_number}`; the UI offers *Discard draft* or *Commit anyway* (`override`). `base-restore {sha}` loads an older version into the draft, `DELETE /imports/{id}` discards. `GET /imports/{id}/base-edit` = diff summary (changed/added/removed blocks by fingerprint, count of edited header/footer parts), started/head numbers, version list.
- **Pins.** Documents keep the version they pinned (`build_spec` unchanged). The builder shows *Newer base document version available: vN* with *Use vN* next to the base picker (admins also get *Edit* there and in Base documents > Details). Editors cannot commit (403); only admins open a session.
- Not done: merging concurrent edits (override replaces by content), texts of removed blocks in the diff (counts only), per-part diff of headers/footers (count only).

## Round 11: dates are DD.MM.YYYY everywhere

- **Rule.** Dates shown or generated: `DD.MM.YYYY`; timestamps in the UI `DD.MM.YYYY HH:mm` (24 h, zero padded, browser time zone). No locale-dependent output. Relative times (`5 min ago`) stay for the first 24 h, older ones show the date.
- **Frontend.** One module `src/dates.ts`: `formatDate` / `formatDateTime` (null/garbage safe; date-only values `YYYY-MM-DD`/`DD.MM.YYYY` use their own parts, never shifted by the time zone; timestamps use local parts), `parseDateInput` (D.M.YYYY or ISO -> ISO, leap years, inline error text), `applyDateFilter` (the `date:` filter for chip sample values), `todayIso` (local day). `ui.fmtDate` = datetime, used by members/invites/base docs/versions/history/commit log/snippet commit list. `src/nolocale.test.ts` fails on `toLocale*String`, `Intl.DateTimeFormat` or `toISOString().slice` anywhere in `src` outside `dates*.ts`. Variable chips with a `date:` filter show the default (or today for `doc.date`) formatted like the exporter. Date variables use `builder/DateInput.tsx` (text input, `aria-invalid` + alert text; stores ISO) instead of `<input type=date>` (whose display follows the OS locale). Calendar popup: not built.
- **Backend.** `app/dates.py`: `parse_date` (DD.MM.YYYY, D.M.YYYY, YYYY-MM-DD (+time), DD/MM/YYYY (MM/DD only when the 2nd number > 12), `5 March 2026`, `March 5, 2026`, Slovenian month names incl. genitive `24. novembra 2026`), `dmy`. `docx_export.context` renders `doc.date`, every `date`-typed variable and revision rows as DD.MM.YYYY; the `datefmt` filter parses any of those and, with an empty format, gives `%d.%m.%Y` (explicit formats, `YYYY-MM-DD` tokens or strftime, are kept); SAVEDATE/CREATEDATE fields get DD.MM.YYYY text. `revision_rows` emit DD.MM.YYYY (stored ISO rows in old documents still render converted). Invite mail: `expires on DD.MM.YYYY`. Import: `Date` header/footer fields become `date:DD.MM.YYYY` chips; the candidates list shows the DD.MM.YYYY reading of a detected date (`display`), and a picked date is declared as a `date` variable with an ISO default.
- **Storage.** `Variables` validation accepts DD.MM.YYYY or ISO for `date` values/defaults, stores ISO. Old values keep working; no migration.
- **Not done / gaps.** Dates inside free text are not rewritten. Word field dates (SAVEDATE etc.) are refreshed by Word with its own picture switch: the exporter writes the cached result only (DD.MM.YYYY), it does not add `\@ "dd.MM.yyyy"` switches, so Word may show another format after a field update. `doc.date` is "today" in UTC at export. Dates in list-variable cells are plain text unless a `date:` filter is applied. docx core properties unchanged.

## Round 12: snippets from an import vs existing snippets

- **Same title = ask.** A title clashes when a snippet in the target folder has the same title (case-insensitive, whitespace-trimmed) or the slug the title would get. `POST /imports/{id}/selection-snippet` answers 409 `{error: "name_exists", conflicts: [{snippet_id, title, slug, head_sha, folder_id, folder_name, last_commit_at, last_commit_author, has_draft, new_title}]}` unless `on_conflict` is given (`create_new_with_suffix` | `update_existing` | `skip`). `POST /imports/{id}/split` takes `on_conflict: {heading index (-1 = preface): action}`; any clashing section without an entry gives the same 409 (with `key`), nothing is written. `POST /imports/{id}/conflicts {folder_id, titles}` is the read-only preview (one entry or null per title) the split dialog uses for its badges.
- **Update existing = the user's draft, never a commit.** The imported blocks replace the content of the caller's draft of that snippet (`vcs.save_draft(rebase=True)`: `base_sha` = current HEAD, so the Commit screen diffs against HEAD and the version bump happens on commit). Snippet id, slug and title stay; `styles` and `variables` are recomputed from the new content; images, style ids and opaque/embedded parts are prepared exactly as for new snippets (`_prep`). If the user's draft holds unsaved changes (`dirty`) the call is 409 `{error: "draft_exists", snippets: [...]}` until `overwrite_draft: true`; a draft equal to its base is replaced silently (nothing to lose).
- **Remembered source.** `snippets.source` (JSONB, migration 0009) = `{import_id, heading_text, block_range_hash}`, written when a snippet is created from or updated from an import. A re-import of a newer manual has another import id, so matching uses `heading_text`, not the id.
- **Bulk update.** `POST /imports/{id}/update-plan {folder_id, headings, targets?}` -> one row per selected heading (`key, title, start, end, blocks, level, match {snippet_id, how: title|source|fuzzy, score}, target, changes {added, removed, changed, same}, has_draft`). Matching in order: same title/slug, remembered source heading (a renamed snippet), fuzzy title (difflib ratio >= 0.7); a snippet matches one heading. `targets` ({heading: snippet id | "new" | "skip"}) overrides the match. Changes are counted against the snippet HEAD by block fingerprint (editor re-save defaults ignored, images compared by their bytes because a re-import stores new image ids). `POST /imports/{id}/update-apply {folder_id, items: [{key, action: update|create|skip, snippet_id?, end?}], overwrite_draft}` cuts the sections at the non-skipped headings (a snippet runs to the next selected heading; `end` pins the end, used by the single-snippet "Update from import…"), writes drafts as above and returns `ImportSnippetOut[]` with `action` = created | updated. A snippet may be the target of one heading only (422).
- **UI.** Selection: dialog "Snippet already exists" (Update it / Create a separate snippet / Choose another title / Skip). Split: per row badge new/exists, select Update existing / Create new (suffix) / Skip (default Update), summary line. Update dialog (import page button and snippet page "Update from import…"): import picker, folder, level 1-3, rows with checkbox, target select (ranked by title similarity, `importSnippets.ts`), change summary, "no changes" rows unticked. Result toast: "Open draft" and "Go to Commit" (`/commit/{folder}?select=id,id`).
- **Gaps.** The change summary in the update dialog is computed for the sections cut at every heading of the chosen level, while Apply cuts at the ticked ones (so unticking a heading enlarges the neighbouring snippet beyond what the row showed). Split/selection `skip` is only available through the API for selection (the UI closes the dialog). Matching is per folder; there is no cross-folder search. `source` is a DB index only, not written to the git `meta.yaml`.

## Round 13: empty revision rows, download of committed versions + render cache

- **Root cause of the empty rows.** Revision rows carried `version/date/author/message/sections/commit`, the table in the user's base document (`hpc-base`, a hand-made `{%tr for row in revision_history %}`) uses `last_edited_date, revision_number, status, edited_by, pages_paragraphs_affected, change_ref`. `Row` renders unknown keys as `""`, so all 8 rows were blank (the Linux Manual has 8 history rows; verified on a copy: all 8 now filled). Fix in one place, `docx_export.revision_rows(spec)` (used by `context`): alias groups (`date|last_edited_date|edited_date`, `version|revision|revision_number|rev`, `author|edited_by`, `sections|pages_paragraphs_affected|pages_affected`, `commit|message|description|change_ref|change`; the first non-empty member fills the rest, so override rows with either key set work), `status` (`Tagged` when the commit has a tag, else `Committed`), rows whose cells are all blank are dropped (builder "new row" blanks), and an empty history gives one row `{version: doc.version, date: doc.date, author, message: "No revisions yet"}`. Not changed: a `{{ document_title }}` heading shows raw in `sections` (heading text is not rendered through variables).
- **Download as of a commit.** `GET /api/documents/{id}/versions/{sha}/export?format=docx|pdf` (viewer+; `sha` = 40 hex, a commit that changed this document, else 404) -> 202 `{export_id, status, cached}`; poll `/api/exports/{id}`, then `/download` (unchanged). `build_spec(ctx, d, at=sha)`: yaml at that commit (own pins, base version, variables), `doc.version` = first tag of the commit or short sha, `doc.date` = commit date, `author` = commit author, revision rows from `git log <sha>` only (plus snippet/base commits up to their pins). Missing variables -> 422 `missing_variables` (UI lists them; no "download anyway"). Each call is an `exports` row (who/when/pins) as before.
- **Cache.** `/files/{org}/cache/{doc}/{sha}-{key32}.{ext}`, `key = sha256(EXPORTER_VERSION | format | spec hash)`. The spec already contains everything the output depends on, so no separate tag-set hash is needed: pinned shas (a `latest` pin is frozen to the snippet HEAD at request time, so a new snippet commit is a miss, i.e. such exports are only cacheable until the snippet changes), variables, base version, org name, and the revision rows including their tags (tags of the document's commits, of pinned snippet commits and base commits) and `doc.version`. Adding/removing/renaming a tag on any commit in the history changes the rows -> new key; stale files are never hit. A tag elsewhere does not invalidate. Overridden (stored) revision tables ignore tags, so tags do not invalidate those. Hit: the file is copied to the new export's path, `cached: true` (UI badge "cached"). Write is atomic (tmp + rename). Cleanup: keep the newest `CACHE_KEEP = 10` files per document (hits touch mtime), the folder is removed with the document; org deletion removes the files root. Bump `EXPORTER_VERSION` when DOCX/PDF output changes.
- **Concurrency.** `_inflight[key] -> export id` under a lock: concurrent identical requests return the same running export (single api process, like the job pool).
- **UI.** Document history (`/history/document/:id`) rows: `DOCX` / `PDF` buttons with progress text, `cached` badge, error banner (missing-variable checklist); the Tags column of that table is the document's tag list. Folder history has no download (a commit there can touch several documents).
- **Gaps.** Not browser-checked in Firefox; no size-based cache limit (count only); two api workers would not share in-flight jobs (they would both render, same bytes into the same file); the 2nd requester of a shared job sees the first requester's export row.

## Round 14: rename commits = display-name override, not a rewrite

- **Decision.** Git commit messages are NOT rewritten: shas are referenced by pins, tags, exports, render caches and drafts, so a rewrite would break all of them. A tenant table `commit_names` (migration 0010: `org_id` NOT NULL + RLS, `scope`, `sha` 40-hex, `name` 1..200, `renamed_by`, `renamed_at`, unique `(org_id, scope, sha)`) holds a per-commit display name. `scope` = folder id (snippets and documents of a folder share its repo) or `base` (the org's base-document repo). The git message stays the immutable original.
- **One resolver.** `vcs.name_fields` / `vcs.commit_out(row, tagmap, names)` is the only place that decides the displayed message; every history item carries `message` (override or original), `original_message`, `name`, `renamed`, `renamed_by`, `renamed_at`. Used by snippet/folder/document history, the revision table (`export.revision_rows` for document, pinned-snippet and base commits: `message`/`commit`/`change_ref`/`description` aliases all derive from it), `build_spec` (version download), base-document versions (`GET /base-documents/{id}/versions`, `head`, base-edit versions) and the Document builder's pin dropdown (it reads the history API).
- **API.** `PATCH /api/folders/{id}/commits/{sha}` `{name}` (editor+) and `PATCH /api/base-documents/{id}/versions/{sha}` (admin). Empty/blank/null `name` or `DELETE` on the same URL = reset. `sha` must be 40 lowercase hex (422) and a real commit of that repo (`git rev-parse --verify sha^{commit}`, 404; base: also a version of that base document). Name trimmed, 1..200 chars, no control characters incl. newline/tab (422). Returns the updated commit item (folder) / version item (base). Cross-org = 404, viewers 403.
- **Cache.** No separate key part: the spec's revision rows already contain the displayed names, so renaming a commit shown in a table changes `spec_hash`/`cache_key` and misses; resetting returns to the original key (the old render is a hit again).
- **Cleanup.** Deleting a folder (with subfolders) deletes its overrides; deleting a document deletes overrides of commits that only it owns (commits shared with snippets/other documents keep theirs); deleting a base document deletes its versions' overrides. Org deletion cascades.
- **UI.** `Rename` button (pencil) on every row of snippet side-panel versions, folder/snippet/document history and base-document versions (table + editor's versions modal); it opens the existing prompt dialog (Enter saves, Esc cancels, `Reset to original` button when renamed). A `renamed` badge's tooltip: `Originally: <git message> — renamed by <name> on DD.MM.YYYY HH:mm`.
- **Gaps.** The tag list API (`GET /folders/{id}/tags`) returns name+sha only and shows no message, so nothing to resolve there. The commit screen's own message is the git message at write time. Exports already rendered keep their frozen spec (the old names). Overrides of a commit shared by several documents in the same folder are per commit, so they show in all of them. Renaming does not keep a history of earlier names.

## Round 16: edit locks, shared drafts, structural revision sections

**Locks.** Tables `edit_locks` (unique org+type+id: the INSERT race is decided by the constraint, the loser re-reads the winner), `lock_requests` (partial unique index = one pending request per entity), `notifications`, `draft_backups` (all org_id NOT NULL + RLS; migration 0012). Entities: snippets and documents. NOT locked: base-document edit sessions (still per user, `imports`) and plain imports (nobody shares them): gaps. A lock row whose `heartbeat_at` is older than `LOCK_HEARTBEAT_TTL_S` (90) is free and is deleted when read. The editor posts `/locks/{snippets|documents}/{id}` (acquire) and then a heartbeat every ~20 s, with a state poll every 4 s in between (`GET` of the same URL) so an incoming request shows up quickly; unload releases with `fetch(..., {keepalive})` instead of `sendBeacon` (a beacon cannot carry the CSRF header); logout releases all of the user's locks. A lapsed lock is simply free; the next opener (or the original holder's next heartbeat) takes it, the draft stays.

**Write guard.** Every write route that touches a snippet/document (draft PUT/DELETE, resolve, restore, bump, delete, commit, import `update-apply`, snippet-from-import update) goes through `locks.require`: held by me -> ok; free -> taken implicitly (API clients and scripts never open an editor; a commit releases a lock it only took for itself); held by another -> 409 `{error: "locked", holder: {id, name, since}}` (also under `detail`). Imports apply: 409 `{error: "locked", snippets: [{snippet_id, title, holder, message: "locked by X"}]}` for all busy items before anything is written (all-or-nothing instead of per item; the client lists them so each can be requested). Viewers cannot lock (403) but can read `GET /locks/{kind}/{id}`.

**Requests.** `POST /locks/{kind}/{id}/request` (editor+): lock free -> you simply get it; cooldown (`LOCK_REQUEST_COOLDOWN_S`, 1800, per requester+entity, counted from the creation of the last request whatever its outcome, admins not exempt) -> 429 `{error: "cooldown", retry_after, retry_at}` + `Retry-After`; another request pending -> 409 `{error: "request_pending", requester, expires_at}`. Holder: `POST /lock-requests/{id}/grant|deny` (404 for anybody else, 409 when no longer pending). Grant: the client saves first, then the lock moves at once. No answer within `LOCK_REQUEST_TIMEOUT_S` (300): `timed_out`, the lock moves to the requester (decided on every heartbeat/state call of that entity and by a sweeper thread every `LOCK_SWEEP_S`=15 s, which finds orgs through the SECURITY DEFINER function `app_lock_orgs()` because RLS hides everything without an org context). The holder's edits are already in the draft (autosave); a later save of the old holder gets 409 locked and the editor shows the "transferred" bar without dropping its local content. If the holder closes the editor or its lock lapses while a request waits, the requester gets the lock immediately. Admin `POST .../takeover` (confirm dialog in the UI) cancels a pending request, moves the lock and notifies the previous holder. Heartbeat/state answer: `{held, holder, incoming (request for me as holder), pending, my_request, cooldown_until, server_time}`; countdowns use `server_time`. `GET /locks` lists active locks with `folder_id` (badges); `GET /notifications` (50 newest + unread), `POST /notifications/read`. Mail: one message to the holder per request (daemon thread, errors only logged).

**Shared drafts.** `drafts`/`document_drafts`: unique per entity (was per user), `user_id` = last editor, `contributors` JSONB [{id,name,email,at}] (latest contribution last) and `transfers` JSONB [{from,to,kind,at}] since the last commit; both vanish with the draft at commit. Migration 0012 keeps the newest draft of an entity and copies older ones into `draft_backups` (payload = the full row); the live database had no entity with two drafts when this shipped (466 snippet drafts, 228 document drafts), so the migration moved nothing there. base_sha/head_sha/conflict behave as before, but a stale draft can only exist from old data now (nobody commits around a shared draft).

**Commit message.** Author = committer. Server-written trailers (stripped from user text like `Snippet-Id`): `Co-authored-by: Name <email>` for every other contributor, `Lock-transferred: A -> B (granted|timeout|taken_over|released)` per hand-over. Only hand-overs while a draft existed are recorded. History items carry `co_authors` and `lock_transfers`; revision rows' `author` = "committer, co-author, ..." (old rows unchanged, key set unchanged).

**Revision sections (replaces round 9's).** `app/sections.py`: the BUILT document (document blocks with snippet pins resolved, builder headings as nodes) is a flat list of top-level nodes; each node gets an anchor: a heading (number from the base document's multilevel list linked to the heading styles: `w:start`, `startOverride`, `lvlRestart`, unnumbered builder headings; builder headings with `numbered` and no list in the base get our own 1 / 1.1 numbering), the caption of its table (SEQ Table paragraph above, or the table's `caption`/`title` attr) or figure (SEQ Figure paragraph below), else the section it sits in, else the snippet title before the first heading. Two versions are diffed block by block (JSON hash, `difflib`), each changed block adds its anchor once; order = position in the new document; `; ` joined; 12 entries then `+N more`. Entry text: `3.2.1 Heading`, `Table 4: Specs (3.2.1)`, `Figure 2: Layout (3.2.1)`; added/removed headings get ` (added)` / ` (removed)`; a renamed heading shows its new text; a deleted paragraph counts for the section it was in. A snippet commit is numbered by substituting that snippet version into the document's current blocks (first use of the snippet); document commits compare the two committed versions, each numbered over its own build ('latest' pins resolve to the current head). Base-document commits use the same rule over the base's own paragraphs. Not listed any more: snippet titles, paragraph text, `Base document / Variables / Linked documents` labels (those changes now give an empty cell). The spec hash already contains the rows, so the export cache needs nothing new. `GET /snippets/{id}/diff` also returns `sections` (relative, no numbers). shortcut: numbers are always decimal (A./i. formats and custom `lvlText` are not reproduced); not checked against real Word.

**Gaps.** Imports/base-edit sessions are not locked; the heartbeat/poll is plain polling (no SSE); `Take over` does not wait for the old holder's pending save; notifications are never deleted; a request answered by closing the editor is recorded as `granted` with transfer kind `released`.

## Round 17: OIDC roles from Keycloak client roles, always auto-provision

**Why.** A Keycloak deployment ran with `OIDC_AUTO_PROVISION=0` and users got "DocGen is invite-only"; the admin wanted accounts created automatically and the role taken from client roles (groups carry the roles named like DocGen's).

**Policy.** In `AUTH_MODE=oidc` a missing account is always created (user, identity, membership in `OIDC_DEFAULT_ORG`); `OIDC_AUTO_PROVISION` is gone (still set to 0: warning at startup, ignored). Authorisation moved from "has an invite" to "has a role in the token". Role = highest of `resource_access.<OIDC_ROLES_CLIENT_ID or OIDC_CLIENT_ID>.roles` (exact dict key), `realm_access.roles` (`OIDC_REALM_ROLES=1`), `OIDC_GROUPS_CLAIM`+`OIDC_ROLE_MAP`; names trimmed, case-insensitive, optional `OIDC_ROLE_PREFIX`. No role = refused before any DB write (message names the client), unless `OIDC_DEFAULT_ROLE` (now empty by default) is set. Role refreshed at every login both ways; the only owner is never demoted (warning). Invites still accepted at login, not required, and do not replace a role.

**Tokens.** Keycloak puts `resource_access` in the access token and userinfo, usually not the id token, so claims come from three sources: id_token (verified as before), access token (decoded only after signature via the same JWKS, issuer, exp with leeway; `aud` deliberately not checked since Keycloak sets it to resource servers/`account`; `azp` must equal the client id when present; `sub` must match; failure = ignored + warning, never trusted unverified; opaque tokens likewise) and userinfo (sub-checked). userinfo is now fetched at every login (one extra request).

**Gaps.** Only tested against the mock IdP (`tests/mock_idp.py` now signs an access token and can put claims in id/access/userinfo separately), never a real Keycloak. A user removed from the group is refused at the next login but an existing DocGen session lives until it expires (no back-channel logout, no removal of the membership). Roles are not synced on a schedule, only at login. A user with an invite but no role is refused.
