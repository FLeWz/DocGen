# Decisions (open choices made)

## Milestone 1
- **Two DB roles.** `docgen` (superuser, from `POSTGRES_USER`) owns tables and runs migrations. `docgen_app` (LOGIN, NOSUPERUSER, NOBYPASSRLS, not owner, DML grants only) is what the API uses. Superusers and owners bypass RLS, so connecting as the owner would silently disable the second wall. The role is created/updated by `alembic/env.py` on every start (password = `APP_DB_PASSWORD`); default privileges grant DML on future tables. Tests assert the role is unprivileged.
- **RLS context** = transaction-local GUCs `app.org_id`, `app.user_id`, `app.invite_hash`, re-applied on every transaction begin. Empty -> NULL -> no rows. `ON DELETE CASCADE` runs as table owner (bypasses RLS), so deleting an org removes its children.
- **Non-org-scoped RLS exceptions** (deliberate, minimal): memberships are also readable by their own `user_id` (login, org list/switch); organizations readable if you have a membership; one invite row is visible when its token hash matches `app.invite_hash` (public lookup/accept). Writes always require `org_id = app.org_id`. `users` and `sessions` are not tenant tables and have no RLS.
- **Switching org** is the only endpoint taking an `org_id` from the client; it is checked against the caller's memberships (404 otherwise). Test enforces no other route accepts `org_id`.
- **Sessions**: opaque 256-bit token in an HttpOnly, SameSite=Lax cookie, SHA-256 hash stored in `sessions`, 14 days, no sliding renewal. `COOKIE_SECURE` env (false in dev; set true behind HTTPS).
- **CSRF**: double-submit. Cookie `docgen_csrf` (JS-readable) must equal `X-CSRF-Token` and carry a valid HMAC (SECRET_KEY) so it can't be forged from a sibling subdomain. Not bound to the session. Applies to all unsafe methods including login/signup/accept.
- **Roles in an org**: admin may manage members up to admin and invite up to admin; only owners grant/modify owners; last owner can't be demoted/removed; anyone may leave (self-delete) unless last owner. Everyone in the org can list members; invites are admin+. Insufficient role -> 403 (the caller already belongs to the org); foreign org objects -> 404.
- **Removed members / deleted orgs**: the session's active org is validated against membership on every request; if gone, the user has no active org (400 on org endpoints, can create/switch).
- **Invites**: raw token only in the email; SHA-256 stored. Resend rotates the token (old link dies) and resets expiry; resending an expired invite revives it. One pending invite per email per org (409). Accepting requires the logged-in email to equal the invite email; unknown-email accept creates the account (email proven by token) and logs in; existing email requires login first (401). Public lookup is `POST /api/invites/lookup` (token in body, not URL/logs) and reveals `user_exists` to the token holder. Single use is enforced with an atomic `UPDATE ... WHERE accepted_at IS NULL`. Expired/used/revoked -> 410, unknown -> 404. If SMTP fails the invite is still created and `email_sent=false` is returned.
- **Emails** normalized to lowercase; signup of an existing email returns 409 (user enumeration accepted for now; no rate limiting yet).
- **Password**: min 10, max 128, argon2id defaults. Login does a dummy verify for unknown users.
- **Ids**: UUIDv4 generated in Python. Roles stored as varchar + CHECK (no PG enum).
- **Sync SQLAlchemy** (psycopg 3, sync endpoints on FastAPI's threadpool); simplest with per-request RLS context.
- **Frontend**: no router library (path switch on `/accept-invite`), plain forms, TanStack Query; dependencies pinned via `package-lock.json`, `npm ci` in Docker.
- **nginx** `web` is the only published app port (`WEB_PORT`); Mailpit UI on `MAIL_UI_PORT`; db/api/pdf are not published. Compose project name fixed to `docgen`.
- **Tests** run in the api image (dev deps included, one image) against a separate database `docgen_test` created on demand; tables truncated per test. Mail is stubbed in tests, real Mailpit used in the compose smoke check.
- **`.env` required**: compose refuses to start without secrets; `make up` copies `.env.example` if `.env` is missing.

## Milestone 2
- **Git via CLI** (`app/git/repo.py`): fixed argv, no shell, `git` in the api image. Commits are built with plumbing (temp index, `hash-object`, `write-tree`, `commit-tree`, `update-ref HEAD new old`) so bare repos need no worktree and a moved HEAD makes the commit fail. Revs from clients must be a 7-40 hex sha or a tag name (`refs/tags/<name>`), never `HEAD`/ranges/options. Repo paths come from UUID objects only and are checked under `REPOS_ROOT`; deleting a folder/org rmtree's its repos after the DB commit.
- **Snippet files**: `snippets/<slug>/content.json` (sorted keys, indent 2, so equal content is byte-equal and diffs are stable) + `meta.yaml` (id first). Rename = dir move in the next commit; old versions are found by the uuid in `meta.yaml` (`git grep`), so history/diff work across renames.
- **Per-snippet history** uses `Snippet-Id: <uuid>` trailers the server appends to each commit message (user-supplied lines of that form are stripped). Commits made outside the app have no trailers and won't show in snippet history.
- **Draft base** = snippet's `head_sha` when the draft was created (NULL for new snippets). Conflict = `draft.base_sha != snippet.head_sha` (another commit touched *this* snippet), not any HEAD movement. An untouched draft (equal to its base) silently follows HEAD. Resolve = PUT merged content and re-base onto HEAD; commit then succeeds. 409 body: `detail = {error:"conflict", conflicts:[{base, theirs, mine, ...}]}`.
- **Commit order**: lock folder row (`FOR UPDATE`) -> DB slug/title flush -> git commit -> DB commit; a git failure rolls the DB back. A crash between git and DB commit leaves a stale index row (HEAD sha behind); no repair job yet.
- **Roles**: viewer reads (incl. changes/history/diff); editor creates/renames/moves folders, snippets, drafts, commits, tags; admin deletes folders (destroys history). New snippets are DB rows without a commit until first committed (visible to the org with `head_sha: null`).
- Display name already existed on `users.name`; no migration needed. No snippet delete endpoint yet.
