# Decisions (open choices made)

## Milestone 1
- **Two DB roles.** `docgen` (superuser, from `POSTGRES_USER`) owns tables and runs migrations. `docgen_app` (LOGIN, NOSUPERUSER, NOBYPASSRLS, not owner, DML grants only) is what the API uses. Superusers and owners bypass RLS, so connecting as the owner would silently disable the second wall. The role is created/updated by `alembic/env.py` on every start (password = `APP_DB_PASSWORD`); default privileges grant DML on future tables. Tests assert the role is unprivileged.
- **RLS context** = transaction-local GUCs `app.org_id`, `app.user_id`, `app.invite_hash`, re-applied on every transaction begin. Empty -> NULL -> no rows. `ON DELETE CASCADE` runs as table owner (bypasses RLS), so deleting an org removes its children.
- **Non-org-scoped RLS exceptions** (deliberate, minimal): memberships are also readable by their own `user_id` (login, org list/switch); organizations readable if you have a membership; one invite row is visible when its token hash matches `app.invite_hash` (public lookup/accept). Writes always require `org_id = app.org_id`. `users` and `sessions` are not tenant tables and have no RLS.
- **Switching org** is the only endpoint taking an `org_id` from the client; it is checked against the caller's memberships (404 otherwise). Test enforces no other route accepts `org_id`.
- **Sessions**: opaque 256-bit token in an HttpOnly, SameSite=Lax cookie, SHA-256 hash stored in `sessions`, 14 days, no sliding renewal. `COOKIE_SECURE` env (false in dev; set true behind HTTPS).
- **CSRF**: double-submit. Cookie `docgen_csrf` (JS-readable) must equal `X-CSRF-Token` and carry a valid HMAC (SECRET_KEY) so it can't be forged from a sibling subdomain. Not bound to the session. Applies to all unsafe methods including login/signup/accept.
- **Roles in an org**: admin may manage members up to admin and invite up to admin; only owners grant/modify owners; last owner can't be demoted/removed; anyone may leave (self-delete) unless last owner. Everyone in the org can list members; invites are admin+. Insufficient role -> 403 (the caller already belongs to the org); foreign org objects -> 404.
- **Removed members / deleted orgs**: the session's active org is validated against membership on every request; if gone, the user has no active org (400 on org endpoints, can create/switch).
- **Invites**: raw token only in the email; SHA-256 stored. Resend rotates the token (old link dies) and resets expiry; resending an expired invite revives it. One pending invite per email per org (409). Accepting requires the logged-in email to equal the invite email; unknown-email accept creates the account (email proven by token) and logs in; existing email requires login first (401). Public lookup is `POST /api/invites/lookup` (token in body, not URL/logs) and reveals `user_exists` to the token holder. Single use is enforced with an atomic `UPDATE ... WHERE accepted_at IS NULL`. Expired/used/revoked -> 410, unknown -> 404. If SMTP fails the invite is still created and `email_sent=false` is returned.
- **Emails** normalized to lowercase; signup of an existing email returns 409 (user enumeration accepted for now; no rate limiting yet).
- **Password**: min 10, max 128, argon2id defaults. Login does a dummy verify for unknown users.
- **Ids**: UUIDv4 generated in Python. Roles stored as varchar + CHECK (no PG enum).
- **Sync SQLAlchemy** (psycopg 3, sync endpoints on FastAPI's threadpool); simplest with per-request RLS context.
- **Frontend**: no router library (path switch on `/accept-invite`), plain forms, TanStack Query; dependencies pinned via `package-lock.json`, `npm ci` in Docker.
- **nginx** `web` is the only published app port (`WEB_PORT`); Mailpit UI on `MAIL_UI_PORT`; db/api/pdf are not published. Compose project name fixed to `docgen`.
- **Tests** run in the api image (dev deps included, one image) against a separate database `docgen_test` created on demand; tables truncated per test. Mail is stubbed in tests, real Mailpit used in the compose smoke check.
- **`.env` required**: compose refuses to start without secrets; `make up` copies `.env.example` if `.env` is missing.

## Milestone 2
- **Git via CLI** (`app/git/repo.py`): fixed argv, no shell, `git` in the api image. Commits are built with plumbing (temp index, `hash-object`, `write-tree`, `commit-tree`, `update-ref HEAD new old`) so bare repos need no worktree and a moved HEAD makes the commit fail. Revs from clients must be a 7-40 hex sha or a tag name (`refs/tags/<name>`), never `HEAD`/ranges/options. Repo paths come from UUID objects only and are checked under `REPOS_ROOT`; deleting a folder/org rmtree's its repos after the DB commit.
- **Snippet files**: `snippets/<slug>/content.json` (sorted keys, indent 2, so equal content is byte-equal and diffs are stable) + `meta.yaml` (id first). Rename = dir move in the next commit; old versions are found by the uuid in `meta.yaml` (`git grep`), so history/diff work across renames.
- **Per-snippet history** uses `Snippet-Id: <uuid>` trailers the server appends to each commit message (user-supplied lines of that form are stripped). Commits made outside the app have no trailers and won't show in snippet history.
- **Draft base** = snippet's `head_sha` when the draft was created (NULL for new snippets). Conflict = `draft.base_sha != snippet.head_sha` (another commit touched *this* snippet), not any HEAD movement. An untouched draft (equal to its base) silently follows HEAD. Resolve = PUT merged content and re-base onto HEAD; commit then succeeds. 409 body: `detail = {error:"conflict", conflicts:[{base, theirs, mine, ...}]}`.
- **Commit order**: lock folder row (`FOR UPDATE`) -> DB slug/title flush -> git commit -> DB commit; a git failure rolls the DB back. A crash between git and DB commit leaves a stale index row (HEAD sha behind); no repair job yet.
- **Roles**: viewer reads (incl. changes/history/diff); editor creates/renames/moves folders, snippets, drafts, commits, tags; admin deletes folders (destroys history). New snippets are DB rows without a commit until first committed (visible to the org with `head_sha: null`).
- Display name already existed on `users.name`; no migration needed. No snippet delete endpoint yet.

## Milestone 3
- **Org style set** (`styles`, tenant table, seeded per org at signup/org create and backfilled by migration 0003): Normal, Title, Heading 1-4 (decimal numbering), Quote, Code, List Paragraph, Table Grid. Content never references a style by uuid but by `style_id`, a Word-style id (`Normal`, `Heading1`), unique per org. Reason: a base document's `styles.xml` uses the same kind of ids, so snippets keep working when a base doc supplies the styles. `style_id`/`kind` are immutable after creation; built-ins can be edited but not deleted; admin writes, everyone reads. Deleting a custom style that content still names is allowed: renderers fall back to `Normal`/`HeadingN`.
- **Base-doc override hook (for M4)**: all style reads go through `app.styles.resolve(repo, base_doc=None)`. M4 implements "styles for base doc X": base doc styles (parsed from its styles.xml, matched by `style_id`) override org styles of the same id; org styles fill ids the base doc lacks (the base doc may instead mark itself "replace", then only its set is offered). The editor/preview take a `Style[]` and don't care where it came from; the API will grow an optional `?base_doc=` on `GET /api/styles`.
- **Content JSON shapes** (TipTap v3; `null` attr = default): `paragraph {styleId|null}` (null = `Normal`, or `ListParagraph` inside a list); `heading {level 1-4, styleId|null}` (null = `Heading<level>`); `table {dynamicList|null}` + `tableRow`/`tableHeader`/`tableCell {colspan, rowspan, colwidth}` (merged cells = colspan/rowspan); `variable` inline atom `{name, default, filter|null}` with filter `upper` or `date:<format>` (e.g. `date:YYYY-MM-DD`); `image` block atom `{imageId, alt, width|null}`; marks `bold`, `italic`, `underline`, `link {href}`; lists `bulletList`/`orderedList`/`listItem`. Variable names: `^[A-Za-z_]\w*(\.\w+)?$`; `row.*` is bound by the enclosing dynamic table and not declared; `doc.*`, `org.*`, `author`, `revision_history`, `linked_documents` are builder built-ins and not declared either. **Dynamic table convention: the last row is the row template**; its cells use `row.field` variable chips.
- **Draft `styles`/`variables`** are computed client-side on every autosave (`extractStyles`, `extractVariables`) and are lists of names only (style ids; variable names incl. dynamic-table list names). Defaults/filters live in the node attrs; the server does not re-derive them.
- **Images**: `POST /api/images` (editor+, multipart `file`, max 10 MiB) is validated by opening the bytes with Pillow (png/jpeg/gif/webp only, no SVG; type from the bytes, never the filename/Content-Type; pixel cap against decompression bombs). Stored at `/files/{org_id}/images/{image_id}.{ext}` (path built from UUIDs, never from the client); `GET /api/images/{id}` is session-authenticated, org-scoped, `nosniff`. Content references images by `imageId` only (never a URL), so renames and old versions don't break. At commit, every referenced image is copied into the git tree as `snippets/<slug>/assets/<imageId>.<ext>` (rename moves the dir along), making the repo self-contained for export. Limits: assets no longer referenced are not pruned from later trees; uploaded images are never garbage-collected from `/files`.
- **Preview** = pure `contentToHtml(doc, styles)` (`frontend/src/editor/render.ts`): A4 page, 2.5 cm margins, style values inlined per block, decimal heading numbering by style level, escaped output, links limited to http/https/mailto. Variable chips show their default (filter applied for `upper`) else `{{ name }}`.
- **Autosave**: 800 ms debounce, PUTs chained so a slow earlier save can't overwrite a later one, flushed on unmount and before "Commit…". The editor reloads server content only on an explicit reload (restore/discard/resolve) or when HEAD/base moved and nothing is unsaved.
- Not done in M3: UI for the org style set (API only), character styles/table styles in the editor (stored, not applied), image resize UI.

## Milestone 4
- **Base documents** live in `/repos/{org}/_base.git` at `base/<id>.docx`; every upload is one commit and one `base_doc_versions` row (number, sha, filename, parsed `styles`, `placeholders`). The sha is the version id that documents pin. No delete endpoint yet. Upload validation (`app/base_docs.py`): <=25 MB, real zip with `[Content_Types].xml` + `word/document.xml` + the Word main content type, no macros/encryption/`..` paths, <=2000 entries, decompressed bytes counted while reading (<=200 MB and <=100x ratio), every `.xml`/`.rels` parsed with defusedxml `forbid_dtd=True` (XXE and entity bombs rejected as 422), then opened with python-docx. python-docx/lxml only touch files that passed this at upload.
- **Placeholders** are whole paragraphs: `{{ CONTENT }}` and `{{ SLOT:name }}`. A base doc without CONTENT is accepted and reported (`placeholders.content=false`); exporting with it fails with a clear error.
- **Styles from a base doc**: `styles.xml` -> Style-shaped rows (no `basedOn` resolution, values sanitized to satisfy `StyleOut`). `resolve(repo, base_doc)` lets base styles override org styles of the same id and keeps org styles for the rest ("replace" mode not implemented). `GET /api/styles?base_doc=<id>` uses the head version.
- **Bundled default** (`default_docx()`): python-docx template + Normal/Title/Heading1-4, header/footer with PAGE/NUMPAGES fields, revision-history and linked-documents tables as docxtpl `{%tr %}` rows, `{{ CONTENT }}`. Created on demand (`POST /api/base-documents` without a file, admin) and used for exports when a document pins no base document. Milestone 4 export *removes* the `{%tr for ... endfor %}` rows (tables keep their header); milestone 5 fills them.
- **Documents** are rows in `documents` + `documents/<slug>.yaml` (id, title, base_document{id,version=sha}, blocks, variables{declarations,values}, links). Drafts are per user (`document_drafts`), created by the first edit/PUT. They are committed through the existing folder commit (`document_ids` next to `snippet_ids`, trailer `Document-Id:`), and `changes` lists them with `kind:"document"`. No 3-way merge: if the head moved since the draft started, commit returns 409 and the draft has to be discarded. Slug rename = delete old file + write new in one commit. Delete = final commit removing the file + DB row.
- **Blocks**: `snippet_ref`, `heading{text,level,styleId,numbered}`, `page_break`, `toc`. "Slot content" is the `slot` field on every block (default `CONTENT`, or a named slot of the base doc); there is no separate slot block type. Block ids are server-assigned uuids when missing (used by bump endpoints).
- **Pins**: `commit` (sha, abbreviations normalised to full), `tag`, `latest`. The referenced folder and snippet must be in the caller's org and the snippet must have a commit, else 404/422 (same body for "other org" and "does not exist"). Default pin from the UI = the snippet's head commit. At export, tags and `latest` are frozen to commit shas.
- **Update available** = pin resolves to a commit whose snippet content differs from head (`C.same`), `newer_commits` = commits with the snippet's trailer in `pin..head`. `latest` pins never show it. Bump preview uses `C.diff`; bump apply writes `{commit, head sha}` into the user's draft.
- **Used by** is an index (`document_refs`) written when a document is committed (one row per snippet block per commit); drafts are not included. Deleting a document deletes its rows.
- **Library** (`GET /api/library/snippets?q=&tag=&folder_id=`): committed snippets only, grouped by folder. `tag` keeps snippets that exist at a commit carrying that tag in their own folder.
- **Export** = `exports` row doubling as the job (queued/running/done/error). `GET /api/documents/{id}/export?format=docx` (GET per the API spec) builds a self-contained `spec` (working copy = draft else head, resolved pin shas, base pin, variables, built-ins incl. the date) in the request, then a 2-thread pool in the api process renders it. `GET /api/exports/{id}` polls, `/download` serves the file. Because the queue is in-process, a restart can strand a row: rows still queued/running after 10 minutes are reported as error. Re-rendering the stored spec gives the same bytes (`export.render_docx`). Exports of a draft are reproducible because the spec snapshot is stored. PDF plugs in as `export.RENDERERS["pdf"]`.
- **Determinism**: fixed core properties (date from the spec), zip entries re-packed with fixed timestamps, numbering/rId/docPr ids are sequential, no random ids.
- **OOXML mapping**: paragraph/heading `styleId` written as `w:pStyle` if the base doc has that style id (else HeadingN, else none = Normal); no direct fonts; bold/italic/underline/link marks as run properties (links only http/https/mailto); lists reuse a base-doc abstractNum with bullet/decimal at level 0 (not tied to a paragraph style) or add one, every ordered list gets its own `w:num` with level restarts; numbered heading blocks use a multilevel numbering, unnumbered ones get `numId 0`; tables via python-docx with `gridSpan`/`vMerge` for col/rowspan (nested tables are skipped with a warning); images from `snippets/<slug>/assets/` at the pinned commit (webp converted to PNG), alt text kept. TOC = dirty complex field + `w:updateFields` in settings.
- **Variables in export**: chips become `{{ name|default(..)|upper|datefmt(..) }}` text runs and, like all `{{ }}` text in the base doc (body, headers, footers), are rendered by a sandboxed jinja env (`*`, `**`, `<<` blocked, no `{% %}`); values are written as XML text nodes so markup in values is inert. Placeholders split across runs are merged into the first run (its formatting wins). Undefined names stay as `{{ name }}` and are listed in the export warnings. Dotted names (`a.b`) become nested dicts. `doc.version` = short head sha or `draft`.
- **Frontend**: native HTML5 drag & drop (library -> blocks, handle -> reorder) plus "Add" buttons; document draft autosave (800 ms) like the snippet editor; preview reuses `contentToHtml` with `?base_doc=` styles; the commit tab handles documents. Not built: restore of an old document version, per-block "view source snippet" link, editing which tags a library filter offers.

## Milestone 5
- **No docxtpl.** The sandboxed jinja env from M4 is kept: docxtpl would need the whole DOCX as one template (and runs unsandboxed unless wrapped); the per-text-node render plus `expand_rows` is ~40 lines and keeps the "values are XML text nodes" guarantee. The base doc still uses docxtpl *syntax* (`{%tr for x in list %}` ... `{%tr endfor %}`), so Word users can author it the usual way. Autoescape stays off on purpose: output goes through lxml text nodes, which escape; turning it on would double-escape.
- **Row repetition** (`docx_export.expand_rows`) is the single mechanism for base-doc tables and for snippet tables marked `dynamicList`: the snippet builder wraps the template (last) row in `{%tr for row in <list> %}` / `{%tr endfor %}` marker rows, so both paths are one code path. Rows between the markers are deep-copied per item and rendered with the item bound (`row`, or the loop variable of the base doc). Only `for x in name[.sub]` is understood; anything else drops the rows with a warning. A list row is a dict whose missing columns render empty (not as a missing variable); `None` renders empty everywhere in revision/linked rows.
- **Render once.** Nodes rendered inside repeated rows are remembered, so a value like `{{ 7*7 }}` typed by a user is never evaluated by the later whole-document pass. Tests cover `''.__class__` style payloads in base doc, snippet text and values (sandbox returns Undefined/raises; text stays inert).
- **Variable types**: `text|date|number|list` (`list` = list of objects; declaration has `columns`). Validated on draft save (422): date = ISO string, number = int/float, list rows = flat objects (<=1000 rows, <=20 fields, scalar values). The built-ins and `row.*` are still never declared.
- **Required variables** (checked at `GET .../export`, before a job exists; 422 `detail = {error:"missing_variables", message, variables:[{name,type}]}`): every *declared* variable, and every chip in pinned snippets without its own default, and every `dynamicList` name, that has neither a value (non-null, non-empty string; `[]` counts as a value) nor a declared default. Variables only referenced by `{{ }}` text of the base document are not pre-checked (would need the base parsed before the job); they stay warnings in the export record.
- **Revision history**: `documents/<slug>.yaml` gets `revision_history: null | [{version,date,author,message}]`. `null` = auto: commits of the document file (`Document-Id` trailer) plus, per pinned snippet, its commits reachable from the pin sha (`Snippet-Id` trailer, so commits newer than the pin don't leak in), de-duplicated by sha, oldest first; version = a tag on that commit else the 7-char sha; message = first line without trailers. Non-null = hand-edited rows used as is ("Reset to auto" sets null again). `GET /api/documents/{id}/revision-history` returns the auto rows for the builder preview. The result is frozen into the export spec. Commits made outside the app (no trailers) are not listed.
- **Linked documents** rows come from `links` (`title`, `doc_id`/`id`, `version`, `url`/`link`).
- Existing documents/drafts without the new key behave as `revision_history: null`; no migration.
- Builder UI: typed variable form (date/number inputs, list editor with columns), revision table with inline editing, missing-variable list with a "Declare" shortcut for undeclared names.

## Milestone 6
- **PDF** = the same DOCX bytes posted to Gotenberg `POST /forms/libreoffice/convert` (`PDF_URL`, httpx, `PDF_TIMEOUT_S`=120, `PDF_MAX_BYTES`=100 MiB counted while streaming, body must start with `%PDF`). Every failure becomes the export row's `error` ("PDF service unavailable", "timed out after Ns", "HTTP 500: <first 200 bytes>", "larger than ...") and download answers 409 like any failed export. No retries.
- **Field refresh**: Gotenberg's `updateIndexes=true` makes LibreOffice rebuild the TOC and evaluate PAGE/NUMPAGES during conversion; verified live (heading shows up in the TOC and body; footer "Page 1 of 1"). The DOCX itself still only has dirty fields + `updateFields`, so Word asks to update on open.
- **Determinism**: DOCX stays byte-identical per spec; PDFs are not promised to be (LibreOffice embeds creation time/ids). The stored spec re-renders the same content.
- Tests: mocked Gotenberg (HTTP server in a thread) for success/500/non-PDF/oversize/timeout/unreachable, plus a live test against the compose `pdf` container (skipped when unreachable) using pypdf for page count and text.

## Milestone 7
- **Import = tenant table `imports`** (`content` JSONB = editable TipTap doc, `warnings`, title, filename) + the original package at `/files/{org}/imports/{id}.docx` (UUID path). The editor saves straight to the row (PUT, 800 ms debounce like drafts; one editable copy per import, not per user). No delete endpoint yet. Upload goes through `base_docs.validate` (zip structure, 25 MB, bomb guard, defusedxml, macros) and then lxml with entities/DTD/network off; `word/document.xml` capped at 30 MB.
- **Parser** (`docx_import.py`): paragraphs/headings (heading = style whose `styles.xml` outline level or id says 1-4; `styleId` = the Word style id, kept), runs with bold/italic/underline, external http(s)/mailto hyperlinks, tables (`gridSpan` -> colspan, `vMerge` -> rowspan, first `tblHeader` row -> `tableHeader`, column widths from `tblGrid`), pictures (png/jpg/gif/webp -> image store via the existing validation, `alt` and width kept), lists (direct `numPr` -> bullet/ordered by the numbering.xml format, nesting by ilvl, `numId` kept as a list attr). Extra attrs `numId` (lists) and `styleId`/`tblPr`/`grid` (tables) are invisible TipTap global attributes.
- **Opaque blocks** = `opaque {kind, xml}`, block granularity: a paragraph with anything unsupported inline (text box, field, content control, equation, SmartArt/chart, comment, tracked change, footnote ref, page break, internal link, section break, legacy objects) becomes one opaque block holding the raw OOXML (with all in-scope namespace declarations), as do body-level unknown elements (sdt, customXml...), nested tables and tables with tracked/irregular rows. One warning per kind with a count. A fragment that would be refused on write-back (see below) is replaced by a visible stub paragraph and listed as "blocked".
- **Write-back validation** (`ooxml.opaque_element`, applied on PUT, on export and when a snippet containing opaque blocks is exported): defusedxml (`forbid_dtd`) then lxml `resolve_entities=False`; root must be a Word element (not `sectPr`); denylist `altChunk`, `subDoc`, `externalData`, OLE objects, controls; field instructions DDE/INCLUDETEXT/LINK/MACROBUTTON/... refused; every `r:*` attribute must name a relationship that exists in the target package. PUT answers 422 on a bad fragment, so export of stored content cannot hit one. Table `tblPr` goes through the same check.
- **Export** = original package with the body replaced (`docx_import.export`): python-docx opens the original, drops every body child but the final `sectPr`, and the exporter's `Builder` (same code as snippet export) writes the content back. styles/numbering/theme/settings/headers/footers/media parts come through (round-trip test compares canonical XML). Import mode (`Builder(rels=...)`) differs from snippet mode in three ways: opaque XML is written verbatim and keeps its `r:id`s; lists reuse their original `numId` when it still exists in numbering.xml (numbering continues across lists); tables restore `tblPr` and `tblGrid`/`tcW`. In snippet mode (selection snippets exported through a document) opaque blocks with relationships are skipped with an export warning, Word 2010+ attributes (`w14:paraId`...) are stripped, and tables use `styleId`/`TableGrid`.
- **Selection** = a range `[start, end)` of top-level block indexes of the stored content (the UI maps the TipTap selection to it after flushing the autosave). The snippet is created as a draft (no commit) with the blocks as they are: style ids and `imageId`s unchanged; images are not copied at this point because they already live in the org image store and the normal commit copies them into the repo. **Split** cuts before every Heading <= level (1 or 2); text before the first heading becomes "Front matter" (skipped if only empty paragraphs); preview is a GET, apply a POST that creates one draft per section in one transaction (max 200).
- **Use as base document** (admin): the original package with the body replaced by a `{{ CONTENT }}` paragraph, stored through `_store` of the base-document router (new base doc, or a new version of an existing one with `base_document_id`).
- **Not kept (listed in warnings with counts):** direct run formatting (font, size, colour, character styles), direct paragraph formatting (alignment, spacing, indent), bookmarks, links to non-web targets, cell shading/borders (table-level properties are kept). Heading detection does not resolve `basedOn`. List items inside a list nest by ilvl order, so a list starting at ilvl 2 is exported at depth 0. Not verified in Word itself, only python-docx, LibreOffice (Gotenberg converts the exports) and structural tests.

## Milestone 8
- **Login throttling** (`app/throttle.py`): failed attempts in process memory, 5 per (ip, email) and 20 per email in 10 min -> 429 + `Retry-After`; a success clears the ip+email counter. The right password is refused too while throttled (else the throttle could be bypassed by guessing). State is per worker and lost on restart (one worker runs); move to a DB table/Redis when scaling out. uvicorn runs with `--forwarded-allow-ips '*'` so the ip is the one nginx puts in `X-Forwarded-For` (the api port is not published, only nginx reaches it). Signup email enumeration (409) is accepted and documented; signup is not throttled. CSRF stays signed double-submit, not session-bound (SameSite=Lax cookie + HMAC); a second cookie is not worth it.
- **Seed** (`app/seed.py`, `python -m app.seed`, run by `entrypoint.sh` when `SEED_DEMO=1`): drives the real API through an in-process `TestClient` (RLS, git and validation are exercised; no second code path), with `mail.send_mail` swapped for a capture to read invite tokens. Idempotent: skipped when `owner@example.com` can log in and "Demo Org" has the sample import (the last step = completeness marker); a partial earlier run is wiped (org deleted, users reused) and redone. Errors never block the api from starting. The sample DOCX comes from `tests/fixtures/sample.py`, which ships in the image (needs only python-docx/Pillow, both runtime deps). The demo password is public (`demo-password-123`): dev only; `.env.example` sets `SEED_DEMO=1`, compose defaults to 0 when unset.
- **Deletes**: `DELETE /api/snippets/{id}` (editor): 409 while a committed document version (`document_refs`) or any draft mentions it; a committed snippet is removed from HEAD in a final commit (history/tags stay), an uncommitted one disappears with its drafts. `DELETE /api/imports/{id}` (editor): row + original file. Org deletion now also removes `/files/{org}` (it only removed repos before).
- **Cleanup** `POST /api/maintenance/cleanup[?dry_run=true]` (admin, own org only): deletes images older than 24 h that no draft, import or git commit of the org names (`git log --all --name-only` finds `assets/<imageId>.<ext>`; an image that ever entered a commit is kept, history/restore still shows it) and files under `/files/{org}/{images,imports,exports}` older than 1 h without a DB row. Manual, no scheduler.
- **Style-set UI**: collapsed "Style set" section on the dashboard (`Styles.tsx`), a table with one form per row; admins edit (PATCH) and add/delete custom styles, others read. `style_id`/`kind` stay immutable.
- **Docker e2e** (`make test` = backend + Vitest + e2e): compose service `e2e` (profile `e2e`, `mcr.microsoft.com/playwright/python` pinned to the playwright version, repo-root build context narrowed by `.dockerignore`) runs `smoke, docbuilder, import, invite` against `http://web` and Mailpit `http://mail:8025`. The DOCX fixture is baked into the image (`E2E_SAMPLE_DOCX`) because the container has no docker. `web` got a healthcheck so `up --wait`/`depends_on` work. The scripts sign up throwaway users in the running stack and retry the first keystrokes in the editor (typing right after a new snippet opens can be swallowed when its draft loads).
- **Acceptance**: `scripts/clean-start.sh` = fresh `git clone` into a temp dir, `.env` from `.env.example` with other ports, `docker compose -p docgen-clean up --build --wait`, login as the seeded owner, volume backup, `down -v`, restore, start with seeding off, check the data, tear down (volumes included). It always passes `-p docgen-clean`.

## Round 2

- **Invite-only**: `ALLOW_SIGNUP` (default `0`, also in compose/.env.example) gates `POST /api/auth/signup` (404 when off); `GET /api/auth/me/config` exposes `allow_signup` so the SPA hides the sign-up form. Accepting an invite as a new user is the only other way to create an account. First user/org on an empty install: `python -m app.manage create-user` (password via stdin/prompt only). `routers.auth.register` is the single account+org creation code used by signup, the CLI, the seed, and the test helper `signup()`. e2e scripts get their users from `scripts/e2e-users.sh` (CLI via `docker compose exec`) with `E2E_TAG`/`E2E_PASSWORD`.
